# v1.0 Usability Plan — three-PR implementation guide

This document is the spec for finishing the v1.0 usability sweep on the
Bioassay Suite app. Eleven items grouped into three sequential PRs.
Each PR is independently shippable: review and merge PR-A before
starting PR-B. **Do not bundle them.**

The work is presentation/UX only. No assay-pipeline math is touched.
All R logic edits live in `app.R`, the `server/` modules, and
`reports/`. All CSS edits live in `www/style.css` (app) or
`reports/report_style.css` (reports).

Conventions used throughout:
- The existing four-token palette (`--c-pass`, `--c-warn`, `--c-fail`,
  `--c-info` + `-soft` variants) is the single source of colour truth.
- The existing `.bs-status-pill` / `.bs-kpi-tile` / `.bs-report-meta`
  classes from the report stylesheet are the design vocabulary; we
  port them to the app stylesheet rather than re-inventing.
- All new strings go through the i18n layer (`tr("…")`). Add English
  AND Spanish strings; if Spanish copy is uncertain, mirror the
  English and flag with `# TODO i18n-es` so a translation pass can
  sweep later.
- All new IDs use the existing `snake_case` convention.

# PR-A — Tier 1: finish-what-we-started (~2 days)

Goal: bring the app to the same finish level as the report. Three of
these items recycle CSS that already exists in `reports/report_style.css`
— porting, not authoring.

## A1. Visual plate preview on the Layout tab

**Problem.** The "Visual plate selector" mode lets the user click
wells to assign roles, but there's no live miniature of the resulting
8×12 plate. Users only see their work *after* upload, by which point
mistakes are expensive.

**Solution.** Render an always-visible 8×12 mini-plate next to the
selector that updates reactively as the user clicks. Cell fill colour
encodes role:

| Role | Fill | Stroke |
|---|---|---|
| Empty | `var(--c-surface-1)` | `1px solid #e3e6ea` |
| Standard | `var(--c-info-soft)` | `1px solid var(--c-info)` |
| Sample | `var(--c-pass-soft)` | `1px solid var(--c-pass)` |
| Blank | `#FAFAFA` | `1px dashed #9aa0a6` |
| NSB | `var(--c-warn-soft)` | `1px solid var(--c-warn)` |
| B0 | `var(--c-fail-soft)` | `1px solid var(--c-fail)` |
| Excluded | `#FDECEA` with diagonal-stripe pattern | `1px solid var(--c-fail)` |

Display the plate at ~280×190 px (well = 22 px). Row letters A-H on
the left, column numbers 1-12 across the top, both 11px Plex Mono.

Implementation:
- Reuse the existing `render_plate_heatmap()` plotly call from
  `reports/plot_functions.R` if the inputs match; otherwise build a
  pure-HTML grid (CSS Grid `8 × 12`, one `<div>` per well, class
  reflecting role). Pure HTML is preferred — no plotly dependency,
  no resize jank.
- A reactive in `server/server_layout.R` (or wherever the visual
  selector lives) emits the well-role matrix; the new
  `output$layout_preview_plate <- renderUI(...)` consumes it.
- Place the preview to the right of the role-picker buttons. On
  narrow viewports stack it below.

Acceptance:
- Click any well in the selector → matching cell in the preview
  updates within one render cycle (no visible lag for a full plate).
- The preview reflects exclusions made via the "Exclude well" action.
- Both Visual selector and Manual matrix-edit modes drive the same
  preview (single source of truth = the layout reactive).

## A2. Status-pill system in the app

**Problem.** The report uses `.bs-status-pill is-pass/warn/fail` for
all status indicators. The app still uses ad-hoc text ("✓ uploaded",
"Warning: …", "Ready"). Inconsistent visual vocabulary.

**Solution.** Port the pill CSS verbatim from
`reports/report_style.css` into `www/style.css` (search for
`.bs-status-pill` in the report sheet — it should be ~15 lines).
Apply at three locations:

1. **Top-bar analysis-state pill.** New element next to the version
   chip. Reactive on a server-side `analysis_state` reactive that
   tracks: `"idle"` → no data, `"ready"` → data loaded, `"running"`
   → fit in progress, `"done"` → fit complete, `"failed"` → fit
   errored. Map to pill class:
   - idle → no pill (don't show)
   - ready → `is-info` (use a fourth pill variant, see below)
   - running → `is-warn` with a spinning dot inside
   - done → `is-pass`
   - failed → `is-fail`

   Add `.bs-status-pill.is-info` to the stylesheet, using
   `background: var(--c-info-soft); color: var(--c-info);`.

   Add `.bs-status-pill .pill-dot` for the spinning indicator —
   a 6px circle that uses CSS `@keyframes pulse` (1s ease-in-out
   infinite). Spinner only when class also has `is-running`.

2. **Upload-tab counts row.** Replace the bare text
   `Standards: 8 · Samples: 24` with two pills. Counts of 0 render
   as `is-warn` ("Standards: 0"); counts ≥ minimum render as
   `is-pass`. The minimum per assay type is in `report_constants.R`
   already.

3. **QC sidebar after fit.** When the user is on the Analysis or
   Quantify tab and a fit has completed, show a four-pill row at
   the top of the right-hand sidebar (or above the main plot if
   no sidebar):
   - R² · value · pass/warn/fail
   - RMSE · value · pass/warn/fail
   - Mean CV · value · pass/warn/fail
   - Mean recovery · value · pass/warn/fail
   Use the existing `assess_qc()` helper that the report already
   uses — do not duplicate the threshold logic.

Acceptance:
- `grep -c "bs-status-pill" www/style.css` ≥ 1
- All three locations render pills, not bare text
- Pill colours match report verbatim (visual A/B against a recent
  rendered report should show identical hex values)
- No raw `✅` / `⚠` emoji introduced in any new code (CI grep stays
  clean)

## A3. Loading state for the Convert button

**Problem.** Report rendering takes 10-20 seconds. During that time
the Convert button stays in its idle state and the page is silent.
Users frequently double-click, then complain about duplicate runs.

**Solution.** Use `shinyjs::disable()` + a button content swap.

```r
observeEvent(input$convert, {
  shinyjs::disable("convert")
  updateActionButton(session, "convert",
    label = tr("rendering_report"),
    icon = icon("spinner", class = "fa-spin"))
  # … existing render logic …
  shinyjs::enable("convert")
  updateActionButton(session, "convert",
    label = tr("generate_report"),
    icon = icon("file-alt"))
})
```

Wrap the render logic in `tryCatch` with `finally =` so the button
re-enables even on error.

Additionally, surface a **progress notification** during render. The
existing `showNotification` system supports `id =` for replacement.
Emit:
- "Validating data…" (0–1s)
- "Fitting curve…" (1–5s)
- "Quantifying samples…" (5–10s)
- "Rendering report…" (10–20s)

Each stage updates the same notification by reusing its `id`. Use
the existing pipeline-stage boundaries in `server/report_pipeline.R`
to drive these.

Acceptance:
- Convert button is disabled and shows "Rendering report (5–20s)…"
  for the entire render
- Double-click within 100 ms produces only one render run
- A single notification updates through the stages instead of
  spawning four notifications
- Button re-enables even if `rmarkdown::render()` throws

## A4. KPI strip on the Analysis tab

**Problem.** The report has a clean KPI strip (R² / RMSE / Cal. low
/ Cal. high / Overall) above the fold. The app does not — so the
app feels less informative than the report it generates. Wrong
direction.

**Solution.** Add the same KPI strip to the top of the Analysis
tab content area, *above* the dose-response plot. Same `.bs-kpi-tile`
CSS, same five tiles, same colour-coded `.is-pass/warn/fail` on the
Overall tile.

The strip is reactive on the fit result. When no fit exists yet,
render the strip with placeholder dashes (`—` in each tile) and a
6th "Run fit" hint tile to the right; placeholder tiles use
`.bs-kpi-tile.is-empty` (defined as `opacity: 0.5; background: var(--c-surface-1)`).

Implementation:
- Port `.bs-kpi-tile` + `.bs-kpi-value` + `.bs-kpi-label` rules
  from `reports/report_style.css` to `www/style.css`. Width tweak:
  app strip should fit five tiles across the analysis tab content
  area without horizontal scroll on a 1280px viewport — verify
  width math.
- Add `output$analysis_kpi_strip <- renderUI(...)` in the analysis
  server module. The fit reactive feeds the values; the existing
  `assess_qc()` helper decides which tile is `is-pass/warn/fail`.

Acceptance:
- Strip is visible on Analysis tab regardless of fit state
- All five tiles render with placeholder when no fit exists
- After a successful fit, tile values exactly match the rendered
  report's KPI strip (visual A/B)
- Overall tile colour matches report's overall tile

# PR-B — Tier 2: report polish (~1.5 days)

Smaller, all in `reports/`. Lower risk than PR-A.

## B1. Inline anchors from QC findings to source tables

**Problem.** The QC summary block reads "Mean recovery 109.5% — Pass".
A reader who wants to inspect the underlying per-standard recovery
values must scroll-hunt to find the back-calculation table further
down the report. Two-three tab-switches in a 30-page report.

**Solution.** Wrap each QC metric value in an anchor link.

```r
sprintf('<a class="bs-qc-anchor" href="#standard-backcalc">%s</a>',
        formatted_recovery)
```

Add to `reports/report_style.css`:
```css
.bs-qc-anchor {
  color: inherit;
  text-decoration: underline dotted;
  text-underline-offset: 3px;
}
.bs-qc-anchor:hover { color: var(--c-info); }
```

Each `kable` table that is the destination of a link needs an
explicit anchor. Use the existing chunk names (`standard-backcalc`,
`sample-results-table`, etc) — knitr emits `id="<chunk-name>"` on the
section header by default; verify and add explicit `<a id="…">`
markers if not.

Mappings to set up:
- "R²" / "RMSE" → `#dose-response-plots`
- "Mean recovery" → `#standard-backcalculation`
- "Mean CV" → `#summary-results-table`
- "Outliers" → `#outlier-results`
- "Hill slope" → `#model-stats`

Acceptance:
- Every numeric value in the QC summary block is a dotted-underline
  link
- Clicking a link smooth-scrolls (use CSS `scroll-behavior: smooth`
  on `html`) to the target section, which is highlighted briefly
  (`:target { background: var(--c-info-soft); transition: background 1.5s; }`)

## B2. "Copy table as TSV" buttons

**Problem.** Researchers paste tables from these reports into
manuscripts. Currently they highlight rows manually, which is
error-prone (browser line-breaks inside cells corrupt the paste).

**Solution.** A small clipboard icon at the top-right of each
`kable` table that copies the table content as TSV.

Use `clipboard.js` (one CDN script tag in the Rmd
`header-includes`). Wrap each table in a `<div class="bs-table-wrap">`
with a `<button class="bs-table-copy" data-clipboard-target="#tbl-N">`
button positioned absolutely top-right (CSS `position: relative` on
wrap; `position: absolute; top: 8px; right: 8px;` on button).

Write a helper `render_table_with_copy(df, …)` in
`reports/report_functions.R` that:
1. Generates a unique ID per call (`paste0("tbl-", sample.int(1e9, 1))`)
2. Wraps the kable output in the div
3. Pre-computes the TSV string and stuffs it into an `<input type="hidden">` referenced by `data-clipboard-text`
4. Replaces every existing `render_table()` call site

Add to CSS:
```css
.bs-table-wrap { position: relative; }
.bs-table-copy {
  position: absolute; top: 8px; right: 8px;
  background: transparent; border: 1px solid #e3e6ea;
  border-radius: 4px; padding: 4px 8px;
  font-size: 11px; color: #5b6573;
  cursor: pointer;
}
.bs-table-copy:hover { background: var(--c-info-soft); color: var(--c-info); }
.bs-table-copy.copied { background: var(--c-pass-soft); color: var(--c-pass); }
```

A short inline `<script>` after the table-copy initialization
swaps the button class to `.copied` for 1.5s on successful copy.

Acceptance:
- Every numeric table in the report has a copy button (top-right)
- Clicking the button copies TSV that pastes cleanly into Excel
  and Word (test both)
- Button briefly flashes green-success after copy
- Print stylesheet hides `.bs-table-copy { display: none !important; }`

## B3. Render the 4PL equation with MathJax

**Problem.** The Methods section discusses the four-parameter
logistic model but doesn't display the equation. Adding it would
take 30 minutes and add a lot of perceived rigor.

**Solution.** In `render_methods_section()` (in `reports/report_sections.R`),
add an equation block in the curve-model paragraph:

```latex
$$y = d + \frac{a - d}{1 + \left(\dfrac{x}{c}\right)^{b}}$$

where  
- $a$ = upper asymptote (response at zero analyte)  
- $d$ = lower asymptote (response at saturating analyte)  
- $c$ = EC50 (analyte concentration at half-maximal response)  
- $b$ = Hill slope (steepness of the transition)  
- $x$ = analyte concentration, $y$ = observed response
```

MathJax is already loaded by `html_document` output. Verify by
checking the rendered HTML's `<head>` for `MathJax`. If missing,
add `mathjax: "default"` to the YAML output block (it's a
`html_document` option).

For DOCX/PDF output, render the equation as a high-DPI PNG via
`latex2png` or fall back to a plain-text representation:
`y = d + (a − d) / (1 + (x / c)^b)`.

Acceptance:
- HTML report renders the equation in LaTeX-quality typography
- DOCX/PDF report renders an acceptable fallback
- The variables (a, b, c, d, x, y) are listed below the equation
  with one-line descriptions

## C2. Sticky stepper on Upload & Preprocess

**Problem.** The stepper is at the top of every tab, but on long
tabs (Upload & Preprocess especially) it scrolls out of view, so
users lose orientation about which step they're on.

**Solution.** `position: sticky; top: 0;` on the stepper
container, with a subtle shadow when stuck.

```css
.bs-stepper {
  position: sticky;
  top: 0;
  z-index: 100;
  background: white;
  transition: box-shadow 0.2s ease;
}
.bs-stepper.is-stuck {
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.06);
}
```

Detect stuck state with an IntersectionObserver shim:
```js
const stepper = document.querySelector('.bs-stepper');
if (stepper) {
  const sentinel = document.createElement('div');
  sentinel.style.cssText = 'position:absolute; top:-1px; height:1px; width:1px;';
  stepper.parentElement.style.position = 'relative';
  stepper.parentElement.prepend(sentinel);
  new IntersectionObserver(([e]) => {
    stepper.classList.toggle('is-stuck', !e.isIntersecting);
  }).observe(sentinel);
}
```

(Put this in a small `www/js/sticky-stepper.js` loaded after the
shiny app boot.)

Acceptance:
- Scroll down the Upload & Preprocess tab → stepper stays visible
  at the top
- Once stuck, stepper has a subtle drop shadow
- The visible step indicator (current pill) updates correctly
  while stuck (no regression in existing stepper behaviour)
- Works in Chrome, Firefox, and Safari

## Regression watch
The earlier passes fixed a lot of subtle things — do not regress them.
After each PR, before merging:

1. `grep -P '[\x{2705}\x{26A0}\x{201C}\x{201D}\x{2018}\x{2019}]' app.R server/ www/ reports/` → 0 (smart quotes + emoji)
2. `grep '"title":\\{"text":"' rendered-report.html` → 0 (plotly titles)
3. `grep 'class="author"' rendered-report.html` → 0 (legacy author header)
4. Render full + compact reports — confirm row shading, table density,
   abbreviations block all still render correctly
5. Top-bar version chip, language selector, stepper all still render

## Cross-PR shared work
Each PR adds CSS to `www/style.css`. Keep the file organized:
- **PR-A** adds `/* §A — Status pills, KPI tiles, plate preview */`
- **PR-B** adds nothing to `www/style.css` (report-only)
- **PR-C** adds `/* §B — Empty states, sticky stepper, drawer */`

Wrap each PR's additions in a comment block so future passes can
locate them. Do not interleave with existing sections.

## i18n
Every new string visible to the user goes through `tr("…")` in
`server/i18n.R`. Add English + Spanish in the same PR that introduces
the string. If Spanish is uncertain, use the English text as
placeholder and mark with `# TODO i18n-es`.

## Out of scope for all three PRs
- Dark mode (deferred)
- Mobile responsive layouts (deferred)
- Any change to the report's `unified_analysis_template.Rmd` chunk
  pipeline — only the helper functions it calls (PR-B only)
- Any change to assay-pipeline math
- Tier 4 items (dark mode, mobile, per-table CSV downloads)
